## SDK & contracts

- **[2026-07-12] No `removeViewer` in `Nox.sol`** — the ACL surface has `addViewer`/`isViewer` but no way to revoke a viewer on-chain. The docs/marketing frame auditor access as "revocable, on-chain"; with the current SDK an `addViewer` grant is add-only. A `removeViewer(handle, addr)` would let integrators build revocable auditor/compliance modes (our Noxus auditor feature wants exactly this).
- **[2026-07-12] Proof owner/app binding makes third-party `fromExternal` submission impossible** — `Nox.fromExternal(h, proof)` calls `validateInputProof(handle, msg.sender, proof, type)`, and `NoxCompute` requires `ownerInProof == owner (== the fromExternal caller's msg.sender)` AND `appInProof == the calling contract`. So an encrypted input created by user A (owner=A, app=C) can only clear `fromExternal` when A is the direct caller of C. A relayer/keeper cannot submit A's input on A's behalf. This is reasonable security, but it isn't called out in the encryptInput docs and it silently rules out "user encrypts, relayer submits" designs (it forced our cross-chain hookData design from inline-relay to per-user pre-registration). Worth an explicit note in the encryptInput guide: the account that will call `fromExternal` must equal the input's owner.
- **[2026-07-12] `@iexec-nox/nox-protocol-contracts` pins `pragma solidity ^0.8.35`** while `nox-confidential-contracts` uses `^0.8.28` — consumers must use solc ≥ 0.8.35 (a very new release) to depend on the SDK library; a note on the minimum supported/tested solc version would help.
- **[2026-07-12] `ERC20ToERC7984Wrapper` is `abstract`** (must be subclassed with an `_update` override choosing optimized vs raw primitives) — there is no directly-deployable concrete wrapper in the package. A ready-to-deploy reference wrapper (or a documented minimal subclass) would speed integration.
- **[2026-07-18] Nox is deployed on only 2 chains, which hard-caps any CCTP-based confidential bridge** — `@iexec-nox/handle`'s `NETWORK_CONFIGS` ships exactly `11155111` (ETH Sepolia) + `421614` (Arb Sepolia). A confidential cross-chain USDC bridge needs BOTH Nox *and* Circle CCTP on each chain; CCTP is live on ~10 testnets (Base, OP, Polygon, Avalanche, Unichain, Linea…), so **Nox is the sole limiter** — our bridge is capped at these 2 chains and can't expand until Nox (NoxCompute + gateway + subgraph) lands on another CCTP chain. A public roadmap of target chains (or an easy self-host override path) would let integrators design multi-chain up front. Our contracts are already domain/peer-parameterized so adding a chain is a deploy+wire — the only blocker is Nox availability.

- **[2026-07-12] `confidentialTransfer(to, euint256 amount)` does not grant the caller ACL on the returned handle** — unlike `confidentialTransferFrom`, which does `Nox.allowTransient(transferred, msg.sender)`. A contract that distributes and then tries to `allow(transferred, recipient)` reverts with the opaque `UnauthorizedSender`. Either symmetry with `confidentialTransferFrom` or a doc note would save a debugging session.
- **[2026-07-12] `UnauthorizedSender(address)` is hard to diagnose** — it carries only the sender, not which handle/grant failed. Root-causing required matching the 4-byte selector against the ACL module. An error including the handle (like `ERC7984UnauthorizedUseOfEncryptedAmount`) would be clearer.

## Infra (gateway / KMS / runner / subgraphs)

- **[2026-07-12] All green during the build.** Latency bench = GO-LIVE both chains (production-shaped reveal RTT: ETH Sepolia median 7.0s / p90 7.5s, Arb 1.7s; KMS is not the bottleneck, block time is). Subgraph lag 1–2 blocks. Gateway/status healthy. No incidents across a full day of E2E runs. Credit where due: the confidential round-trip is fast enough for a live 4-minute demo.
- **[2026-07-18] Opaque `403 access_denied` from the Handle Gateway when decrypting a freshly-credited balance** — right after a confidential distribution, reading the recipient's new `confidentialBalanceOf` handle and calling `decrypt` intermittently returns `403 {"error":"access_denied"}`, then succeeds on a retry seconds later. It looks like ACL/index propagation lag at the gateway rather than a real authorization failure. We made the post-distribution balance read best-effort with retry, but the error is indistinguishable from a genuine permission problem — a distinct code (or a documented propagation delay after an ACL-granting tx) would save debugging.
- **[2026-07-18] Bidirectional works cleanly** — running the same contracts as a reverse pair (Arb→ETH) needed zero Nox-side changes; the chain-scoped handles + per-chain gateway signing behaved correctly in both directions. Credit: the chainId-in-handle enforcement made the reverse leg safe by construction.
- **[2026-07-21] Token-free PublicNode RPCs are non-archive (~64-90 blocks), blocking historical event verification** — `ethereum-sepolia-rpc.publicnode.com` and `arbitrum-sepolia-rpc.publicnode.com` reject `eth_getLogs` outside a tiny recent window with `-32602 "Archive requests require a personal token"` (ETH) / same on Arb where sub-second blocks shrink the window to seconds. Direct contract reads (`epochInfo`) work fine, but confirming that a *specific* past epoch's `EpochSettled`/`EpochDistributed` event actually fired is impossible on these endpoints once it ages out. On-chain state remains authoritative, but auditors/verifiers reproducing event-level history need an archive RPC (paid token or the subgraph). Worth documenting a recommended archive/subgraph endpoint for verification tooling.
